Noise-floor measurement

After Loop 8, the pattern was suspicious: Loop 5 hit 50%; every subsequent variant (L5a, L6, L7, L8) returned to 33%. This could mean: (a) Loop 5 was a real signal that the other changes broke, or (b) Loop 5 was a random fluctuation around a 33% mean. Re-ran the Loop 5 code (no changes from when it scored 50%) twice to discriminate.

What this means for the loop framework

The revert rubric ("loss-set gain ≥1 → keep") assumes a single 6-case cohort can detect a 1-case improvement. The noise-floor measurement shows that's incorrect: a single 6-case run has ~17pp standard deviation just from LLM temperature variance, and the per-case binary outcome flips ~50% of the time on at least one tested case. The rubric was effectively rolling dice.

What WAS demonstrated

  1. The watchdog infrastructure works. Loop 4 attempt 1 silently hung on a missing jq dependency; if I'd waited on the 30-min wakeup I'd have wasted another 25 min. The watchdog Monitor (60s polling on log size + completion regex) catches stuck cohorts within 3 min.
  2. The revert rubric correctly fires reverts. 5 of 6 changes were reverted per the rule (gain=0 or holdout regression). The 6th — Loop 5 — was correctly identified as suspicious through the noise-floor follow-up.
  3. Per-case qualitative observations are real even when aggregate is noisy. L1 NF1 case ALWAYS produced Neurofibroma #1 across 8+ runs (every variant). L2 NF1 flipped between Neurofibroma and NF1. That tells us L1 and L2 have different underlying difficulty — L2 is on the boundary of the LLM's syndrome-naming behavior.
  4. Failure classes from prior work were validated as residual. NF1 feature-vs-syndrome and DEE4 phenotype overlap remain unsolved at the pipeline layer with prompt/parameter changes.

Recommendations

1. Fix the measurement before running more loops

  • Either use n≥25 cases per cohort (smooths single-case noise) — adds ~$15/loop and ~50 min wall
  • Or run 3 trials per variant on the n=6 set, compare distributions (Wilcoxon paired across the 6 PMIDs) — adds 3× compute
  • Power calc says ~150 cases needed to detect a real 5pp gain at 80% power. The n=6 framework can only detect ≥30pp shifts cleanly.

2. Re-baseline before declaring any future result

Run a 3-trial v27.0 cohort to fix the noise floor. Compare any variant against this distribution, not against a single baseline reading.

3. Loop framework is well-suited for big mechanistic changes, not parameter tuning

The 1-line changes attempted here (slice limits, panel size, threshold) produce effect sizes likely <5pp. n=6 can't see them. Reserve the loop for changes plausibly producing ≥15pp gains, OR move to n≥25.

4. Promising directions that ARE plausibly >15pp and worth a proper-power loop

  • Grader-side credited-set fixes — Mondo mosaic-variant relations, ADTKD umbrella ancestor logic. From prior loop work, this would lift L2 + L8 (separate ADTKD loop) immediately, with a hard signal that's independent of LLM stochasticity.
  • Deterministic post-finalize feature-vs-syndrome reranker — work preserved on branch loss-loop/feature-vs-syndrome-stack. Would override the LLM's lexical naming via Mondo IS_A classification of the top-1.
  • Multi-vote ensemble — run the pipeline 3× per case and use majority on top-1. Reduces noise from LLM stochasticity at the consumer level; arguably the most direct fix for the problem this report documents.
