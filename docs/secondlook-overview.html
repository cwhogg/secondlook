System Overview

SecondLook

How the rare-disease diagnostic pipeline and its evaluation harness fit together — from a patient typing symptoms into a form to a ranked differential, refinement, and benchmark accuracy measurement.

Pipeline v17 architecture v18 refinement flow 9,275 KB disease profiles Next.js 14 · TypeScript

At a glance

SecondLook helps patients investigate the possibility of a rare disease they may have been missing. The patient describes symptoms; an AI pipeline grounded in a curated knowledge base of ~9,200 rare diseases produces a ranked differential diagnosis; an optional refinement step asks the patient 1–5 targeted yes/no questions to tighten the result; the patient leaves with named tests, where-to-get-it guidance, and a downloadable PDF report. A separate evaluation harness measures the pipeline against published benchmarks.

Data residency

All patient data lives in the browser's localStorage and sessionStorage only. There is no server-side persistence of analyses, no user accounts. Starting a new analysis clears the cache.

The pipeline (v17)

The diagnostic pipeline runs as a single SSE-streamed call at /api/analyze-patient-v2. The orchestrator (lib/pipeline/orchestrator.ts) coordinates ten stages. Most stages are LLM-driven; a few are deterministic (KB retrieval, dedup, family enrichment). Provider mix is per-stage: OpenAI for triage, specialists, and the o3 critic; Anthropic Claude for evaluator, synthesiser, finaliser, and clarifier.

OpenAI Anthropic Deterministic Optional
0
Symptom extraction — parse free-text into structured terms
gpt-4.1-mini UMLS

Patient's narrative is split into structured symptoms. Each symptom is mapped to a UMLS CUI / SNOMED term using searchUMLSWithFallbacks() with intelligent fallback strategies. The output is a clean list of named medical findings, plus a list of excluded findings (things the patient explicitly says they don't have).

Routes: /api/parse-symptoms Files: lib/umls-search.ts
1
Triage — body systems, acuity, KB candidate retrieval
gpt-4.1-nano KB retrieval

The triage agent classifies the case across body systems, sets an acuity level (routine / urgent / emergent), and ranks specialist relevance. It then triggers semantic retrieval against the disease KB via Upstash Vector (text-embedding-3-large, 256d, similarity ≥ 0.60) to pull the top-K candidate diseases the specialists will see.

Files: lib/agents/triage-agent.ts, lib/knowledge/retrieval.ts
2
Specialists — 5 domain agents in parallel
o3 high

Five specialist agents run in parallel against the patient case. Each gets a reranked slice of KB candidates relevant to their specialty (except general-internist, which gets none — by design, as the un-anchored counterweight). Each agent emits 3–7 ranked hypotheses with: supporting + contradictory evidence mapped to specific patient symptoms, clinical reasoning, cardinal features, rule-out features, recommended diagnostic tests, and (v18+) candidate clarifying questions.

Selection rule: always include geneticist + general-internist as anchors, then fill the remaining 3 slots from the triage ranking. Rare diseases are disproportionately genetic; the un-anchored internist hedges against KB-anchoring bias.

3
Dedup & merge — union specialist hypotheses
Deterministic

Same-disease hypotheses from different specialists are merged: evidence items are unioned, domain confidence is preserved per specialist, name variants are kept, candidate clarifying questions are unioned. The canonical name is chosen by KB anchor, specialist consensus, or shortest variant. Matching uses exact-normalized, substring, alias-map, and KB-anchored paths.

Files: lib/agents/dedup-normalizer.ts Telemetry: dedupStats per group, suspicious pairs flagged
4
Claude evaluator — criteria-grounded scoring
claude-opus-4-7

Two-track scoring on a single 0–100 scale. KB-matched diseases are scored against their structured diagnostic criteria (Brighton, Ghent, RCD, etc.) — counting met / not-met / unknown criteria. Non-KB diseases are scored via clinical reasoning quality. Both tracks use the same scale to avoid systematic bias against non-KB diagnoses. Each hypothesis is also flagged with information gaps and evidence quality.

Files: lib/agents/claude-evaluator.ts, lib/agents/evidence-evaluator.ts
5
Claude synthesiser — rank the full evaluated pool
claude-opus-4-7

Claude ranks every evaluated hypothesis (widened funnel — was top-10 only in earlier versions). Output includes ranked diagnoses with probability scores, consensus level (strong / moderate / weak / divergent), confidence calibration, critical gaps, differential clusters, and excluded common diagnoses. The full ranking passes downstream so the critic and finaliser can promote entries that would otherwise be dropped.

Files: lib/agents/claude-synthesizer.ts
6
o3 critic — second-opinion challenge to the ranking
o3 high

OpenAI o3 reviews Claude's ranking and emits structured critique suggestions: promote, demote, reorder, merge, flag-gap, or add. Each suggestion carries cited patient evidence and a confidence score. The add action — proposing a new diagnosis not in Claude's draft — is gated on a minimum confidence floor.

Files: lib/agents/o3-critic.ts
7
Low-confidence escalation — broaden the investigative pathway
Deterministic

If all top-5 scores < 40, or consensus is weak / divergent, or top-diagnosis reliability is rated low, an escalation context is injected. This recommends broader pathways — WES/WGS, geneticist referral, undiagnosed-disease programs like the NIH UDP — and is folded into the finaliser and report prompts.

8
Claude finaliser — select the patient-facing top 10
claude-opus-4-7

Claude reviews each o3 suggestion and decides whether to honour it. The output is the final top-10 the patient sees. Decisions are logged per hypothesis (changesFromFirstPass) so the report can show what o3's critique actually changed vs Claude's first synth pass. The 10-cap is firm; entries not in the final 10 are dropped.

Files: lib/agents/claude-finalizer.ts
8.5
Clarifier — pick 1–5 follow-up questions
claude-sonnet-4-6 v18, fail-soft

Reads the top-ranked hypotheses + the candidate pool of clarifying questions the specialists emitted, and picks 1–5 patient-answerable yes/no questions with the highest discriminating power. Each picked question carries a per-hypothesis affectsDiagnoses map (ifYes / ifNo → rules-in / supports / weakens / rules-out / neutral). Fail-soft: if no candidates exist or Claude errors, the result is just no clarifying questions and the rest of the pipeline is unaffected.

Rules for picked questions: patient-answerable ("Has a doctor ever told you you have X?", "Do you experience Y?"), clean yes/no, high discriminating power, non-redundant, spread across top hypotheses. Lab values only if critical AND likely-known by the patient.

Files: lib/agents/clarifier.ts
9
Family enrichment — umbrella vs subtype callout
Deterministic

For top-5 hypotheses with 3+ KB sibling subtypes (e.g. CMT 1-X, Loeys-Dietz 1-5), surface the family's differentiating test (modality + per-subtype unique findings). The report shows: "this belongs to a family of N subtypes; modality X can determine which." Up to two family enrichments per analysis.

10
Report generator — format the patient-facing report
gpt-4.1-mini

Final formatting pass. Assembles overall assessment, patient-hypothesis analysis (whether the patient's own guess was likely / unlikely + reasoning), data gaps, recommended tests with rationale and urgency, immediate actions, specialist referrals, follow-up timing, and red flags.

Files: lib/agents/report-generator.ts

Knowledge base

Per-profile shape

  • Diagnostic criteria — formal frameworks where they exist (Brighton, Ghent, RCD, 2017 hEDS, etc.), with major/minor classification.
  • Symptom tiers — pathognomonic (>90%), common (>50%), occasional (10–50%), rare (<10%). Each symptom carries frequency % and body-system classification.
  • Demographics — onset ages, inheritance, sex predilection.
  • Prevalence — Orphanet classification where available.
  • Genetic findings — gene names, inheritance pattern.
  • Differential diagnoses, red flags, common mimics — for use by both specialists and the report.
  • confidenceInData — flag indicating whether the profile has been human-reviewed (most Orphanet-enriched profiles are medium; some original entries are low).

Retrieval engine

Hybrid: semantic (vector) + multi-factor scoring. The matcher weighs symptom overlap (tier-weighted), body-system overlap, demographic fit, and prevalence prior. KB-variant injection (Pass 5) and gene-evidence top-1 rewrite (v24+) target umbrella-vs-subtype misses.

Orphanet enrichment

Build pipeline at scripts/enrich-from-orphanet.js reads four Orphanet XML datasets and folds them in:

  • HPO phenotypes → replaces symptom arrays
  • Natural history → onset ages + inheritance
  • Epidemiology → prevalence classifications
  • Gene associations → genetic findings

Refinement (v18)

After the initial analysis lands, the patient can refine the differential by answering 1–5 targeted yes/no questions. Refinement is optional — the patient can skip directly to recommendations.

Question generation (pipeline stage 8.5)

Specialists emit candidate questions per hypothesis during stage 2 (constrained to patient-answerable yes/no formats). Stage 8.5 picks the 1–5 with highest discriminating power across the top hypotheses.

Patient answers (UX)

/results/refine renders the questions with Yes / No / Don't know radios. Don't-know is no signal — the hypothesis is untouched.

Answer-to-evidence mapping (API)

/api/refine-diagnosis turns each yes/no answer into new EvidenceItems on the affected hypotheses: rules-in → strong supporting, supports → moderate supporting, weakens → moderate contradictory, rules-out → strong contradictory. The augmented pool then re-runs Claude evaluator + synth.

Before/after presentation

The refined page shows rank-change badges (e.g. #3 → #1) and score deltas (e.g. 55% → 78% (+23)), plus a "dropped out of the top 10" section. The refined results replace the analysis in sessionStorage so downstream pages and the PDF report use them.

Testing harness

Two parallel evaluation surfaces: a synthetic-case generator at /testing for iterating on prompts and architecture, and a real-published-case benchmark at /eval for paper-comparable accuracy measurement.

/testing

app/testing/page.tsx · password-gated

Automated three-step harness: Generate → Run → Grade. Click "Run New Test" to chain all three.

  1. Generate — Claude Sonnet 4.6 creates a synthetic patient case with a ground-truth diagnosis at a chosen difficulty (1–5, multi-dimensional). Optionally biased to a body-system category.
  2. Run pipeline — full V2 pipeline analyses the generated case (in dev, rate-limiter disabled).
  3. Grade — Claude Sonnet 4.6 grades the pipeline output against ground truth using a 7-tier rubric with partial credit for correct disease category / organ system.

Test cases persist in Upstash Redis via /api/admin/test-cases. The dashboard groups history by test version (v1 legacy → v4 Orphanet-enriched KB) and shows top-1 / top-3 / top-5 / top-10 rates per difficulty cohort.

Auto-chained progression: generate → pipeline → grade all run on a single click. Difficulty levels are multi-dimensional, not pure prevalence.

/eval

app/eval/page.tsx · password-gated

Runs Phenopacket2Prompt cases (Robinson et al., Eur J Hum Genet 2026) through the live pipeline + OpenAI / Claude baselines side-by-side, so SecondLook can be compared apples-to-apples against published baselines.

  • ~9,600 published cases with OMIM gold IDs at scripts/benchmark-data/en.jsonl.
  • Cohorts: standard50 is the headline 50-case cohort run across SecondLook + OpenAI baseline + Claude baseline as matched trios.
  • Matched-trio view: per-case side-by-side ranks. Clickable rows filter the trio table.
  • Eval versions: v1 / v2 distinguish phenopacket source.

The eval table shows: clinical Top-1, EXACT Top-1, FAMILY Top-1, and the depth metrics at Top-3 / Top-5 / Top-10. Headline number: SecondLook minus average-baseline margin.

Grader versions

Graders evolved separately from the pipeline. The default grader on normal eval runs is v2 (LLM tier-based). v4 is the paper-faithful one, designed for cross-paper comparability.

v1
Legacy string matcher. Plain substring + alias lookup.
v2
LLM grader (default). Claude Sonnet judges rank + applies the 7-tier rubric with partial credit. Lenient enough to give credit for the right family / organ system.
v3
Tiered LLM grader. Splits credit into EXACT / FAMILY / VARIANT tiers explicitly.
v4
Paper-faithful Mondo grader. Grounds predictions in Mondo ontology IDs and scores against creditedSetFull (exact + skos:exactMatch equivalents → 1.0) and creditedSetPartial (transitive IS_A ancestors → 0.5). Asymmetric: gold-is-descendant-of-prediction. Designed to be directly comparable to published Exomiser / GPT-4o baselines. Opt-in only — runs as offline regrade via scripts/grade-eval-v4.ts.

Infrastructure & conventions

Stack

  • Framework — Next.js 14 (App Router), React 19, TypeScript
  • UI — Tailwind CSS + Radix (shadcn/ui)
  • Content — MDX with gray-matter frontmatter for blog / FAQ
  • Validation — Zod everywhere on API boundaries
  • Storage — Upstash Redis (test cases), Upstash Vector (KB embeddings)
  • Deployment — Vercel

Stream protocol

The V2 pipeline streams progress via Server-Sent Events. Event shapes are defined in lib/types/pipeline.ts as a discriminated union: extraction, triage, specialists, specialist-done, specialist-failed, evidence, synthesis, report, complete, plus a 10-second heartbeat on long stages. The client (components/analysis-loading.tsx) renders a live timeline with mm:ss elapsed timer per active stage.

Provider separation

  • Analysis flow: mixed providers per-stage (OpenAI for triage/specialists/critic, Anthropic for evaluator/synth/finalize/clarifier).
  • Testing framework: Anthropic-only. Strict — keeps OpenAI analysis quota from being exhausted by test runs.

Budget & safety

  • Per-analysis budget cap defaults to $2.00 (configurable via ANALYSIS_BUDGET_CENTS); tracked in lib/pipeline/budget.ts.
  • Rate limiting (production only): 3 analyses per IP per 10 minutes. Disabled in dev. Admin bypass via X-Cohort-Bypass header for benchmark runs.
  • Patient data: localStorage / sessionStorage only. No server-side persistence.

SEO & privacy

  • Step pages, analysis, testing, results all have noindex layouts.
  • robots.ts disallows /step-*, /results/*, /testing, /api/*.
  • Custom 404 page; FAQ structured data on the homepage; Vercel Analytics + SpeedInsights.
