## Goal

Replace our two ad-hoc eval graders (**v2** and **v3**) with a single **v4
grader that faithfully replicates the grading methodology of the published
Phenopacket2Prompt benchmark** — the paper our `/eval` dataset comes from. The
point is to produce Top-1/3/10 numbers that are *directly comparable* to the
paper's published baselines (Exomiser 35.5% Top-1, best LLM 23.6% Top-1, GPT-4o
~20% Top-1) and to our own SL/OpenAI/Claude eval runs.

Our current graders use fuzzy string matching and LLM tier judgments that are
**more lenient and higher-variance** than the paper's protocol, so our headline
numbers are not honestly comparable to the literature. v4 fixes that.

## Usage model — REQUIREMENT (confirmed by the repo owner, non-negotiable)

v4 is an **opt-in regrade-and-compare** tool, **not** a replacement default grader.
Hold this invariant throughout:

- **v2 and v3 remain the default graders.** Every normal eval run still produces
  `grading` (v2) and `tieredGrading` (v3) exactly as today. v4 changes nothing
  about the default flow.
- **v4 never runs automatically.** It is triggered explicitly, on demand, against
  a cohort that has **already completed** (the pipeline differentials are already
  stored). v4 only re-scores existing stored differentials — it does **not**
  re-run the pipeline, call OpenAI, or regenerate cases. Cheap to run on any
  finished cohort.
- **v4 is additive, not destructive.** It attaches a separate `v4Grading` object
  to each case **alongside** `grading`/`tieredGrading`; it must never overwrite or
  delete the v2/v3 gradings.
- **Primary deliverable = an offline regrade-and-compare script** (`scripts/
  grade-eval-v4.mjs`) that takes an existing cohort and prints v4 Top-1/3/10 side
  by side with the v2/v3 numbers for the same cases. A live `/eval` button is
  **optional**; if built, it must be an explicit "Regrade with v4" action on an
  already-graded cohort, never part of the default run path.

The goal is to be able to ask, after the fact, "what would this finished run score
under the paper's protocol?" and compare — without disturbing the existing
headline numbers.

## The published grading methodology we must replicate

Source: Robinson et al., "Systematic benchmarking demonstrates large language
models have not reached the diagnostic accuracy of traditional rare-disease
decision support tools," *Eur J Hum Genet* 2026 (medRxiv 2024.07.22.24310816;
dataset = Phenopacket2Prompt, Zenodo DOI 10.5281/zenodo.15065293). Methods,
quoted verbatim:

1. **Grounding free-text predictions to ontology IDs.** "each item in the
   differential diagnosis generated by the LLM was converted to Mondo Disease
   Ontology terms as follows: first, items that matched exactly to a Mondo
   disease label or synonym were assigned Mondo terms using the Ontology Access
   Kit (OAK) ... and the remaining items were assigned the best matching Mondo
   term above an empirically determined threshold using **CurateGPT**." They
   grounded 94.0–95.6% of items.

2. **Correctness criterion (three acceptance routes).** "An item from the
   differential diagnosis was considered correct if the disease identifier for
   the diagnosis **matched** the identifier for gold standard diagnosis from the
   case report **exactly**, or was mapped as **equivalent** to the identifier of
   the gold standard diagnosis in Mondo, or if the gold standard diagnosis was a
   **close descendant of the LLM's diagnosis identifier** in Mondo." The
   descendant rule is deliberately asymmetric clinical leniency: it credits
   "geleophysic dysplasia" (umbrella the model named) when the gold standard is
   "geleophysic dysplasia 2" (specific subtype) — i.e. **gold is a descendant of
   the prediction**. It does NOT (per the literal text) credit the reverse
   (model names a subtype, gold is the umbrella).

3. **Metrics.** Top-1, Top-3, Top-10 placement of the first correct item. No
   Top-5, no MRR in the headline. (We can additionally compute Top-5 and MRR for
   our own use, but the paper-comparable headline is Top-1/3/10.)

4. **No human review.** Fully automated and deterministic by design, to avoid
   curator subjectivity.

## Analysis: what I found and why v4 is needed

This section records the investigation behind this spec so you don't have to
re-derive it. Everything here was confirmed by reading the repo and the paper's
Methods; numbers are exact, not estimated.

### Finding 1 — the gold OMIM id is present but discarded
Each eval row in `scripts/benchmark-data/en.jsonl` is
`{ ppkt_id, diagnosis: [{ id: "OMIM:NNNNNN", label }], case_description }`, and
`app/api/admin/eval-case/route.ts` passes the full `diagnosis` array (id + label)
to the client. So **the ontology id the paper grades against is already in hand.**
But the grader request schemas collapse ground truth to a bare string:
`grade-test/route.ts` takes `groundTruth: { diagnosis: string, ... }` and
`grade-test-tiered/route.ts` takes `groundTruth: { diagnosis: string }`. The id
is dropped before grading. Consequence: today we grade disease *names against
names*, never *ids against ids* — the opposite of the paper's design. This is the
single most important defect v4 corrects, and it's cheap to fix because the id is
already flowing through `eval-case`.

### Finding 2 — our matching is structurally more lenient than the paper's
- **v2** (`lib/grading/deterministic-match.ts` + Claude): a 15-tier score table
  that awards partial credit for **ICD-10 3-character category prefix match**
  (`icd10PrefixMatch`, tier `icd10-match`, score 40–58) and for **organ-system
  only** (LLM-promoted, 25–45). It also matches names via substring containment
  and a **Dice bigram coefficient ≥ 0.75** plus a "≥2 shared medical terms"
  heuristic. None of these have any analog in the paper — under the Mondo
  exact/equivalent/descendant rule, an ICD-category hit or an organ-system hit is
  a **miss**.
- **v3** (`grade-test-tiered`): Claude opus-4-7 assigns EXACT/VARIANT/FAMILY/
  SIBLING/UNRELATED per entry, and the headline `isTop1` counts **EXACT *or
  VARIANT*** at rank 1. VARIANT = "engine named the umbrella, truth is a numbered
  subtype" — this direction (prediction broader than gold) *is* roughly the
  paper's descendant rule, so VARIANT is defensible. But v3 is an **LLM judgment
  call with no ontology grounding**, so it's non-deterministic, unauditable, and
  can drift case-to-case; the paper deliberately chose a computational method to
  avoid exactly this. FAMILY ("wrong numbered sibling") and SIBLING ("related
  disease, different entity") are *not* credited in v3's Top-1, which is correct
  — but they inflate the lower tiers we sometimes report.

Net: v2/v3 give credit the paper would score as misses (ICD category, organ
system, fuzzy-string near-hits), and v3 substitutes an LLM's opinion for an
ontology lookup. Both push our reported accuracy **above** what a paper-faithful
grader would yield.

### Finding 3 — the comparability problem (why this blocks honest claims)
Our memory currently headlines "SL 45.8% clinical Top-1 vs OpenAI 38.2% vs Claude
30.4%" on the v23.1 std-50 cohort, graded by v3 (EXACT-or-VARIANT). The paper's
published numbers are Exomiser 35.5% / best-LLM 23.6% / GPT-4o ~20% **Top-1, under
Mondo exact/equivalent/descendant grading**. These two scales are **not the same
measurement** — a 45.8% under our lenient grader cannot be placed next to 23.6%
under theirs and called "better." Until we grade with the paper's protocol, any
claim that SL beats the published baselines is unfounded on grading grounds alone
(this is *separate* from, and additional to, the OpenAI baseline ±10pp case-mix
variance already noted in memory). v4 is what makes the cross-comparison legitimate.

### Finding 4 — the 694-distinct-gold structure makes faithful grading cheap
All 9,587 golds are OMIM ids and there are only **694 distinct** ones. The
paper's correctness rule is monotone in the gold: the credited Mondo ids for a
gold are exactly `{gold_mondo} ∪ equivalents ∪ ancestors(≤N)`. So the entire
ontology dependency collapses to a **precomputed 694-row table**, computed once
offline. Runtime never touches the Mondo graph — which both sidesteps the Vercel
bundle-size failure mode (the 425MB embeddings deploy break in memory) and makes
grading deterministic and instant.

### Conclusion
The right move is a single deterministic, ontology-id-based grader that (1) uses
the OMIM gold id we already have, (2) grounds free-text predictions to Mondo via
exact-label/synonym + a constrained Claude fallback (mirroring OAK + CurateGPT),
(3) credits a prediction only on the exact / equivalent / gold-is-a-close-
descendant rule, and (4) reports Top-1/3/10 plus grounding rate. It runs as an
**opt-in, additive regrade pass** over already-completed cohorts (see "Usage
model" above) — it does **not** replace v2/v3 as the default, and v2/v3 remain the
headline graders on normal runs. v4's job is to re-score a finished run under the
paper's protocol so we can compare. **Expect v4 to report a lower SL Top-1 than
v2/v3 did on the same cases** — that's expected, because v4 is stricter; if it
doesn't drop, the new grader is still leaking leniency somewhere and should be
investigated before the numbers are trusted.

## v4 design

### Principle
Grade in **ontology-ID space**, not string space. Gold = the case's OMIM id.
Predictions = free-text disease names from the pipeline (and from the
OpenAI/Claude baselines via `app/api/admin/eval-baseline/route.ts`), each grounded
to a Mondo id, then tested against the gold's "credited set."

### Match logic (asymmetric, faithful)
A predicted item is **correct** iff its grounded Mondo id `P` satisfies any of:
- `P == gold_mondo` (exact), OR
- `P` is **equivalent** to `gold_mondo` in Mondo (Mondo equivalence/xref), OR
- `gold_mondo` is a **close descendant of `P`** (i.e. `P` is an ancestor of
  `gold_mondo` within N is-a hops — prediction is the broader umbrella).

`gold_mondo` = the Mondo class equivalent to the gold OMIM id (via Mondo's
OMIM xref / `skos:exactMatch`). The first correct item's rank → Top-1/3/10.

### Exploit the 694-gold fact: precompute a "credited set" table
Because "correct" means *P equals/equiv/ancestor-of gold*, the set of Mondo ids
that would be credited for a given gold is fixed and finite:
`creditedSet(gold) = {gold_mondo} ∪ equivalents(gold_mondo) ∪
ancestors(gold_mondo, ≤ N hops)`.

Precompute this **offline** for all 694 distinct gold OMIM ids and store as a
small JSON map `{ "OMIM:273750": ["MONDO:...","MONDO:...", ...], ... }`. Grading
then reduces to: ground each prediction → Mondo id → membership test in
`creditedSet(gold)`. This keeps the heavy ontology graph **out of the runtime /
Vercel bundle** (see deployment constraint) and makes grading deterministic and
fast.

### Grounding free-text → Mondo id (detailed — read this whole section)

Grounding (resolving a free-text disease name to a Mondo id) is the step that
most affects v4's fairness, so it gets the most detail. Name mismatch is an
**artifact**, not a diagnostic failure — a system that writes "von Recklinghausen
disease" for "neurofibromatosis type 1" got the diagnosis right and must not lose
credit for the wording. The published protocol agrees: it *includes* a grounding
stage (OAK exact + CurateGPT fuzzy, ~94–95% grounded) precisely to neutralise
this artifact. So building a strong grounder is **faithful to the benchmark, not
a leniency hack** — provided it obeys the two invariants below.

#### Invariant 1 — grounding is GOLD-BLIND
The grounder resolves each predicted name to **its own true Mondo node**, and
**must never see the gold answer** (the case's OMIM id, its label, or its credited
set). Matching happens *afterward*, comparing the resolved id to `creditedSet
(gold)`. The litmus test for ANY grounding rule you add: *would it produce the
same Mondo id if it had no idea what the correct answer was?* If yes → legitimate
recall improvement. If it nudges vague/uncertain names *toward* the gold → that is
the leniency leak v4 exists to remove; reject it. Concretely: the grounding
function signature must not take the gold as a parameter. Keep grounding and
matching in separate functions/modules so this can't accidentally happen.

#### Invariant 2 — IDENTICAL treatment of SecondLook, OpenAI o3, and Claude
All three models' differentials are grounded by the **same code, same Mondo
release, same synonym set, same fuzzy threshold, same prompt**. No model gets a
shortcut. In particular: **do NOT grade SecondLook via the ontology ids its own
pipeline emits while grading the baselines from text.** That would hand SL a
grounding advantage the paper never gave any model and silently break
cross-model comparability. SL's outputs go through the identical text grounder as
o3 and Claude. (SL's internal ids have exactly one sanctioned use — the audit
path below — and it never touches grading.)

#### The grounding pipeline (apply per predicted item, all models)
Stage A and B mirror the paper's OAK + CurateGPT. Stages 0 and the expansions are
gold-blind recall boosters that raise *everyone's* grounding rate equally.

0. **Normalize.** Lowercase; strip parentheticals; normalize punctuation/hyphens/
   spacing; handle "X-linked", roman numerals, and trailing type numbers. Reuse/
   adapt `normalizeDiagnosis()` from `lib/grading/deterministic-match.ts`. Also
   derive parenthetical alternates (reuse `extractParentheticalNames()`) so
   "NF1 (von Recklinghausen disease)" yields both candidate strings.
A. **Deterministic exact match (OAK analog).** Look the normalized string (and its
   alternates) up in a prebuilt `mondo-labels.json` index
   `{ normalizedLabelOrSynonym -> mondoId }`, built offline from Mondo using the
   **full synonym set** — primary label + `hasExactSynonym` + `hasRelatedSynonym`
   (record which synonym scope matched; you may later choose to trust exact only).
   A few MB of strings — safe to ship in the runtime bundle.
A2. **Alias/abbreviation expansion (gold-blind).** Before falling through to the
   LLM, try a deterministic alias table: common disease abbreviations (CVID, NF1,
   ADTKD, DEE…) and gene-symbol→disease aliases. Build this offline from Mondo's
   synonym set + abbreviation synonyms; do NOT hand-curate per disease (that
   violates "generalize, never specialize"). This recovers a large slice of the
   long tail for all models at once.
B. **Constrained fuzzy fallback (CurateGPT analog).** For items still unresolved,
   resolve with an LLM. **Anthropic-only per project rule — use Claude, never
   OpenAI.** Constrain hard: retrieve a shortlist of candidate Mondo terms (top
   lexical and/or embedding neighbours of the predicted string), pass ONLY that
   shortlist + the predicted name (NOT the gold), and have Claude pick the single
   best-matching Mondo id or return `none` below a confidence threshold. It must
   never invent an id or pick outside the shortlist. Use the same model, prompt,
   and threshold for every model's items.
C. **Record provenance per item:** which stage grounded it (exact / synonym /
   alias / fuzzy / none), and for fuzzy, the confidence. Items that reach `none`
   are **not correct** — never silently dropped, never guessed toward the gold.

#### Audit path (SL ids — diagnostic only, NEVER grading)
SL's finalizer already matched a KB profile carrying an OMIM/Orphanet id. Capture
that id alongside SL's free-text output and, **separately from grading**, compare
"what the text grounder resolved SL's name to" vs "the id SL intended." This
yields the number that actually answers the user's question — *how much of SL's
grounding loss is artifact* (grounder failed on a name SL had a clean id for) vs
*real* (SL named something genuinely un-mappable). Report it. It must not change
any grade. (Baselines have no such id, which is exactly why this can't be a
grading input without breaking Invariant 2.)

#### Recall target & honesty boundary
Target the paper's grounding rate (~94–95%) **for every model**. What you cannot
solve away: names that are genuinely not in Mondo (truly novel entities,
"undiagnosed", a description rather than a disease) — those stay misses, because
that's real, not artifact. If SL's v24 gene-evidence rewrite emits names that are
systematically harder to ground than plain disease names, the honest fix is to
make SL emit cleaner names (or use the audit path to quantify it), **not** to make
the grounder more forgiving for SL.

### Metrics output
Per case: per-item grounded-id list **with grounding stage/provenance**,
first-correct rank, and `top1/top3/top10` booleans (+ optional `top5`,
`reciprocalRank`). Cohort, reported **per model side by side**: Top-1/3/10 rates,
**grounding-success rate (must be reported per model so differential grounding
loss is visible)**, count of unmappable golds, and the SL artifact-vs-real
grounding-loss breakdown from the audit path. Keep the headline = Top-1/3/10 to
match the paper. If SL's and the baselines' grounding rates diverge materially,
flag it — a Top-1 gap riding on a grounding-rate gap is an artifact, not a real
diagnostic gap.
